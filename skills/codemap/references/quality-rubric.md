# 语义审阅与交付

机器检查通过后，仍需逐项核对：

1. 组织视角符合用户意图，问题、标题与实际覆盖一致；一条正常路径没有被称为全部实现。架构图的概览能回答模块职责与联系，不只是改名后的步骤列表。
2. 每层提供新的解释，不只是重复标题；父层可由孩子及其证据支撑。
3. 每条调用关系有具体调用点；动态分派有绑定证据或明确未知，条件未丢失。
4. 错误、返回、权限、锁和资源路径没有被误删。省略理由具体，行号和原文可检查。
5. 同一函数的别名没有被当成另一个实现；实体关系和控制流程分开计数。架构的共享对象、接口与关键依赖有依据，不为凑连通而虚构关系；模块排列及导读顺序不冒充执行顺序。
6. 证据均属于所记录快照；dirty 内容不会伪装成远端已提交版本。
7. 运行 validate/build/inspect，查看生成 HTML 的导读路径、缩放、搜索和源码。浏览器不可用时明确记录该限制。

事实错误、错引证据、遗漏关键条件、虚构关系和无法阅读的主路径阻断标准交付。解释建议和非关键补充可记作开放项。最终说明区分源码比对、语义审阅、交互验证和读者实验，不能用其中一项冒充其他项。
