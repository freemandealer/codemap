# 01 · 产品需求

## 1. 定位与问题

CodeMap 是面向代码理解的语义地图。用户真正需要回答的是：“这段系统为什么这样工作，关键责任由谁承担，哪些具体代码实现了它？”目录树只给出文件组织，调用图只给出部分调用关系，逐函数摘要缺少全局叙事；CodeMap 把问题、抽象、关系和证据放在同一阅读空间。

首要使用者是接触陌生模块的开发者、阅读系统源码的学习者，以及需要向他人讲解实现的技术作者。初期不承担完整 IDE、运行时调试器或代码正确性证明工具的职责。

成功体验：读者先看懂目标与边界，选择一个职责区域放大，沿关键关系找到实现，查看必要的分支和状态，再通过面包屑回到整体；全过程知道“我在哪里、这里为何存在、还隐藏了什么”。

## 2. 典型场景

| 场景 | 输入目标 | 读者应获得的答案 |
| --- | --- | --- |
| 系统学习 | 理解 VFS 如何抽象不同文件系统 | 共用对象、接口分派、一个具体操作的实现路径 |
| 接手项目 | 理解一次支付请求如何落账 | 业务边界、幂等与事务、成功和失败路径 |
| 深入模块 | 理解调度器如何选下一个任务 | 决策条件、核心数据结构、函数内关键分支 |
| 技术分享 | 向同事解释缓存回填机制 | 有阅读起点、可逐级探索且可分享的地图 |

首版优先验证单仓库、单目标。多语言仓库可以纳入分析，但只对实际读取并有证据的范围作出实现结论，不承诺一次性准确还原整个代码库。

## 3. 输入契约

必填输入是 `repo_path` 与 `question`。可选输入包括阅读者基础、语言、入口符号、包含/排除目录、期望深度、文件/符号预算、源码分享策略以及输出目录。

默认基础是“了解该语言，不了解该模块”。默认中文讲解，保留原始代码标识符。默认只读仓库，不执行目标项目的安装、构建或启动脚本。Git 仓库记录具体提交和工作区变化；非 Git 目录记录输入文件内容指纹。

对于“理解整个 Linux”之类超大目标，先生成边界明确的概览和一条深入路径，同时显式列出未展开部分。目标不明确但有合理入口时继续分析，并记录假设；确实存在互斥解释时才询问。

## 4. 范围与优先级

`P0` 是 v0.1 完整阅读闭环，`P1` 是闭环稳定后的增强，`后续` 明确不进入本期。

| 编号 | 优先级 | 需求 | 可验收行为 |
| --- | --- | --- | --- |
| FR-01 | P0 | 目标驱动的代码选择 | 地图记录问题、范围、入口、排除项与未解决问题 |
| FR-02 | P0 | 递归讲解层次 | 一个根主题；任意合理深度；每个子层回答父层提出的问题 |
| FR-03 | P0 | 语义缩放 | 在至少一条真实路径上连续经历主题、机制、函数/步骤、源码呈现；不能只缩放字体 |
| FR-04 | P0 | 稳定地图布局 | 同一内容在连续缩放中保持所属区域，反向缩放能恢复概览 |
| FR-05 | P0 | 随尺度变化的关系 | 粗线可展开为有实际成员的细线；混合深度时端点仍正确 |
| FR-06 | P0 | 核心代码 | 展示准确原文、行号、省略位置和省略原因，不冒充可编译的完整函数 |
| FR-07 | P0 | 证据与不确定性 | 实现结论可定位文件/行；推断与未知可区分；动态目标无法确认时保留未知 |
| FR-08 | P0 | 定位与返回 | 面包屑、返回上层、适配全图、搜索符号/标题、选择节点和关系 |
| FR-09 | P0 | 独立阅读 | 打开导出的 HTML，断网仍可完成缩放、搜索、看内嵌代码和证据 |
| FR-10 | P0 | 分享与内嵌 | 用户托管后可复制指向主题/节点/关系的链接，提供可用 iframe 示例 |
| FR-11 | P0 | 可重复渲染 | 固定输入、编译器与选项得到一致语义和布局；阅读不请求模型 |
| FR-12 | P0 | 错误可解释 | 无效引用、无法核验的源码或预算超限能定位对象；失败不覆盖上次有效输出 |
| FR-13 | P0 | 基础可访问性 | 键盘可逐层阅读；地图有同步文本大纲；颜色不是唯一状态信号 |
| FR-14 | P1 | 导读与筛选增强 | 多条命名阅读路线、关系类型筛选、关联符号定位、可选缩略地图 |
| FR-15 | P1 | 增量生成 | 仓库变化后只更新受影响内容，明确证据过期，尽量维持 ID 和布局 |
| FR-16 | 后续 | 文字编辑与用户链接 | 不提供首版编辑器；预留独立内容覆盖层 |
| FR-17 | 后续 | 在线生成与商业化 | 上传仓库、兼容 API、BYOK、平台付费、账号和协作均后置 |

分享是首版要求，但内置托管服务不是。浏览器阅读地图和 Agent 生成地图是两个不同产品阶段，不把后者偷偷放进前者。

## 5. 信息层次的产品规则

推荐阅读梯度如下，但不是强制的固定五层：

| 阅读尺度 | 主要问题 | 推荐呈现 |
| --- | --- | --- |
| 主题概览 | 整个功能是什么？ | 一句核心解释、范围、3–7 个主要职责 |
| 职责/机制 | 各部分如何协作？ | 责任区域、重要对象、聚合关系 |
| 实现单元 | 谁具体完成任务？ | 函数/类型、输入输出、前置条件、副作用 |
| 函数内过程 | 顺序、分支和状态如何变化？ | 结构化步骤、条件边、循环或简短解释 |
| 核心源码 | 具体是哪几行？ | 原始片段、行号、保留的控制语义、证据详情 |

逻辑模块可以跨多个文件；一个文件也可参与多个职责。只有一句清楚解释的短函数可以直接进入代码，不强制造出空洞的步骤层。无法逐级解释的外部库作为边界实体出现，标注“范围外”，而不是伪造其内部结构。

父节点必须表达子节点的共同作用；子节点不是机械拆分成均匀大小。建议一个层面有 3–7 个主要元素，过多时按责任继续分组；建议不等于必须把 2 个真实元素补成 3 个。

## 6. 必须保留的源码语义

“核心”指与阅读问题相关，不能简单等同于正常路径。影响返回值、权限、资源所有权、锁顺序、事务、引用计数、重试/回退的代码不能因看似周边而被隐去。允许折叠，但摘要必须说明条件和结果，且读者可定位原文。

日志、统计、与目标无关的适配可省略；每个省略区间保留真实行号和原因。不同文件或不连续行不得拼成貌似连续的可执行代码。显示代码与 Agent 编写的伪代码必须有不同标签；首版源码卡只接受从快照提取的原文。

## 7. 边界与异常体验

- 找不到入口：交付候选入口及证据，说明无法闭合的部分。
- 间接调用/反射：显示已找到的绑定依据；否则连到未知目标或候选集合，不标成必然调用。
- 同一函数被多模块使用：显示同一实体的多个讲解引用，不重复统计为多个函数。
- 缩放已到最细：保持源码可读，提示已到当前地图的证据边界，不继续生成内容。
- 关系过密：显示确定性合并的关系组和准确数量，点开成员；不得无声丢弃。
- 发布环境禁止 iframe 或脚本：提供普通链接与静态说明；产品不承诺绕过宿主限制。
- 代码有变化：新旧快照分开；旧地图仍解释旧快照，不悄悄改到最新分支链接。

## 8. 非功能目标与验收方法

以下为原型阶段待测目标。基线为 8GB 内存的现代笔记本、桌面浏览器、1440×900、离线文件；测试记录具体硬件和版本。

| 指标 | v0.1 目标 | 验证方式 |
| --- | --- | --- |
| 地图规模 | 500 个讲解节点、1,500 条原子关系、源码内嵌不超过 2MB | 固定压力样例 |
| 同屏复杂度 | 默认不超过 80 张主体卡、200 条可见边 | 投影统计与边预算测试 |
| 首次可交互 | 单文件 HTML 不超过 5MB 时目标 ≤2 秒 | 冷启动 10 次，记录中位数和 P95 |
| 手势响应 | 常用场景帧时间 P95 ≤33ms；停止手势后 150ms 内完成细节更新 | 30 秒脚本化缩放和平移 |
| 可追溯性 | 所有标为源码事实的结论和关系均有有效证据引用 | 结构、源码核验及语义抽审 |
| 阅读有效性 | 5 位目标读者中至少 4 位能在 10 分钟内回答预设 3 个问题并找到源码 | 首次使用观察，记录错误和迷路点 |
| 可携带性 | 无网络请求也能完成核心阅读 | 浏览器断网测试 |

不以“覆盖全部代码行”衡量成功。覆盖率只针对已声明问题和路径清单，分母由地图作者写明；未经执行验证的调用图不能被称为完整运行轨迹。
