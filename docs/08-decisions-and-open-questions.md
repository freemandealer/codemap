# 08 · 设计决策与待验证项

## 1. 用户明确的产品约束

| 编号 | 已明确的要求 | 设计响应 |
| --- | --- | --- |
| U1 | 用不同尺度解释不同抽象程度的代码 | 递归讲解树 + 局部语义缩放 |
| U2 | 输入代码目录和理解目标 | 先定问题与范围，再按路径分析 |
| U3 | 通过 Skill 让 Code Agent 梳理 | 生成端复用宿主 Agent；首版不提供模型接入服务 |
| U4 | 渲染无需 LLM | IR、布局编译器和离线查看器分离 |
| U5 | 粗连线可展开为接口之间的细关系 | 原子关系表 + 端口 + 运行时尺度投影 |
| U6 | 支持分享链接和内嵌 HTML | 单文件 HTML + 用户静态托管 + iframe |
| U7 | 内容编辑、链接添加和生成网站后置 | v0.1 不实现这些界面或服务 |

## 2. 本文档采用的建议基线

以下由设计推导而来，用于让开发方案具体化；不冒充已经由用户逐项确认的决定。

| 编号 | 基线选择 | 理由 | 何时重新评估 |
| --- | --- | --- | --- |
| D1 | 一张地图围绕一个问题 | 避免全库大图无法阅读，便于判断覆盖 | 多主题用户研究出现稳定需求 |
| D2 | 实体图与讲解树分离 | 代码复用和环不能塞进严格目录树 | 保持此核心边界 |
| D3 | 局部屏幕面积决定 LOD | 同一层级不代表同一信息密度 | M1 手势体验验证 |
| D4 | 规范节点承担默认关系投影 | 避免别名导致边数相乘 | 以后增加显式多视图投影策略 |
| D5 | 递归区域布局，Agent 不写坐标 | 可重现，减少生成负担 | 特殊流程布局需要更多约束时 |
| D6 | 先用 SVG/DOM | 代码文本、可访问性与小规模交付优先 | 实测性能不达标再评估 Canvas/WebGL |
| D7 | 单文件离线产物 | 分享和博客嵌入简单，无运行服务 | 数据规模确实超限时增加分块模式 |
| D8 | C 系统代码作主要复杂案例 | 与用户 VFS 示例一致，可验证间接调用和资源路径 | 用户选择不同首要受众时 |
| D9 | 无后台编辑器 | 先验证阅读价值；数据仍可由 Agent 再生成 | 阅读闭环稳定之后 |

## 3. 开发前需要通过实验确认

- **第一优先：缩放是否真的增加理解。** 用 M1 原型让读者从整体进入源码再返回，观察是否每层有新信息。
- **第二优先：连线密度。** 用共享函数、循环、高扇出和混合深度测试，确定默认聚合与同屏预算。
- **第三优先：裁剪是否可信。** 选择有错误、清理和动态分派的代码，请熟悉实现的人审阅。
- **第四优先：可读尺寸。** 360×220、520×260 等是原型参数，需根据真实内容和设备调整。
- **第五优先：生成成本。** 记录实际读取文件数、模型上下文和修正次数，不预先保证任意仓库的生成速度。
