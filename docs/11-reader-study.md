# 11 · 首次阅读试用方案

目标是验证读者能回答问题并定位原文。源码检查、自动化交互通过后仍需真实读者试用；不能由实现者代填结果。本文件目前是可执行方案，没有任何已完成的参与者记录。

## 样例与步骤

使用 `npm run demo` 生成的三份实际项目候选地图：CodeMap 构建流程、fast-deep-equal、json-schema-traverse。MiniFS 是教学材料，不计作实际项目。

先对三份地图分别安排源码审阅，检查事实、条件、未知回调、许可和主路径；记录阻断问题及修复后的复查。然后邀请 5 位了解 JavaScript/TypeScript、不了解目标模块的读者，每位选择其中一份地图，在 10 分钟内独立作答。三份地图都至少有一位参与者，参与者在计时前不能看答案。不要在计时中指导点击路径。

开始前只说明：“这是可以逐层深入源码的离线地图，可以用大纲、搜索和返回功能。”记录浏览器版本、设备、地图的 `build-receipt.json` 指纹。允许口头反馈，但答案必须同时给出文件和行号依据。

## 主持人答案依据

这一节在计时前不展示给参与者；最终仍应以地图对应的源码快照核对行号。

- CodeMap：仅提供 `--repo` 时在 build 分支再次调用 validateMap；不匹配收据抛 E_VALIDATION_RECEIPT，发生于输出替换前；两次 writeAtomic 分开执行，HTML 写入失败可能留下新收据与旧 HTML。依据 `src/cli.ts:72–84`、`src/validator.ts:154–165`、`src/packager.ts:50–55`。
- fast-deep-equal：长度或对应元素不同立即失败，次序有意义；valueOf 分支提前返回，不再比较普通键；Object.keys 不包含 symbol，默认入口没有循环访问缓存。依据样例 `source/index.cjs:14–20`、`:24–41` 及完整 equal 函数。
- json-schema-traverse：pre → 子层 → post，异常会传播，没有 finally 保证 post；属性路径为 `/properties/a~0~1b`；default 在 skipKeywords 中，未知数组不会因 allKeys 自动递归，布尔值被对象守卫跳过。依据样例 `source/index.cjs:45–93`。

## 设备补测

至少在一种真实触控板和一种真实触屏设备上，执行缩放、拖动、源码滚动、返回主题与 iframe 激活/退出。记录系统和浏览器版本及截图；脚本化 wheel、窄视口或设备模拟不算真实硬件验收。
